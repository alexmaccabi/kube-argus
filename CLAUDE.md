### Build / run
```bash
# Frontend (must run before backend; Go embeds web/dist/)
cd web && npm install && npm run build

# Backend (serves embedded frontend on :8080)
go run ./cmd/server

# Single-binary build (matches Dockerfile output)
cd web && npm run build && cd .. && go build -o kube-argus ./cmd/server

# Full container path
docker compose up
```

Local URL: http://localhost:8080. Override with `PORT`.

### Pre-flight checklist before declaring a change done
This mirrors `.github/workflows/ci.yaml`:

- Backend changes: `go vet ./... && go build ./cmd/server` — both must pass
- Frontend changes: `cd web && npm run build` (this runs `tsc -b` first, so it type-checks) — must pass
- UI changes: load the affected view in the browser. There is no test suite — visual verification is the only check.

There are **no Go tests and no JS/TS tests** in this repo. Don't fabricate `_test.go` files or `*.test.tsx` files unless the user asks for a testing strategy.

### Approval-required actions
Don't take these without explicit user confirmation:

- **Tagging a release** (`git tag v*` and pushing) — fires `release.yaml`, builds multi-arch images, publishes the Helm chart, and creates a GitHub Release.
- **Editing `CHANGELOG.md` off-cycle** — it's the release-notes source of truth; mid-cycle edits drift the next release.
- **Bumping `deploy/helm/kube-argus/Chart.yaml`** `version` / `appVersion` — both must move together (see the Helm rule in the imported file).
- **Modifying `.github/workflows/release.yaml` or `pages-sync.yaml`** — exercised by tags/landing-page changes; mistakes are loud.
- **Force pushes, branch deletions**, or anything that rewrites public history.

### Common pitfalls

- **Stale embedded frontend.** The Go binary embeds `web/dist/` at compile time. If you change React code and skip `npm run build`, `go run`/`go build` still serves the previous assets. Rebuild the frontend first.
- **Unregistered handlers.** A new `apiXxx` function does nothing until it's added to the `mux.HandleFunc` block in `cmd/server/main.go`.
- **`useFetch` SWR cache.** Responses are cached for 30s keyed by URL. Changing a handler's payload shape without changing the URL means viewers see stale shapes for up to 30s — bump the URL/query-param when the contract changes.
- **`.gitignore` and `cmd/server/`.** The repo has a `/server` entry that's meant to exclude the bare binary, not the package directory. Past commit `cee0a98` fixed an accidental shadow — don't regress it.
- **Helm vs raw manifests drift.** Any change to `deploy/helm/kube-argus/templates/deployment.yaml` or `clusterrole.yaml` must also land in the matching file under `deploy/k8s/`, otherwise non-Helm users diverge.
- **`values.schema.json`.** Every new value in `deploy/helm/kube-argus/values.yaml` must also be added to the schema, or ArtifactHub stops rendering the values table.

### Adding a new resource view (end-to-end checklist)

1. Backend: new file `cmd/server/<resource>.go` with `apiXxx` handlers; use `j` / `je` / `jk8s` and `cache.mu.RLock()`.
2. Register routes in `cmd/server/main.go` (list endpoint `/api/<resource>`, action endpoint `/api/<resource>/` with trailing slash).
3. Gate mutations: `requireAdmin` or `requireAdminOrJIT(ns, kind, name)`.
4. Shared types in `web/src/types.ts`.
5. List view at `web/src/components/views/<Resource>View.tsx` using `useFetch(url, 10_000)`.
6. Detail companion `<Resource>DetailView.tsx` if drill-down is meaningful (see PodDetailView, NodeDescribeView, WorkloadDetailView, ServiceDetailView, HPADetailView for the established pattern).
7. Wire routing in `web/src/routing.ts` and `App.tsx`.
8. URL state: reflect filters/selection in the URL (shareable links).
9. Theme: verify in both light and dark.

### Style reminders

- Match existing Go style (`gofmt`, short helper names — don't rename `j` → `writeJSON` for "clarity").
- Match existing React style — no Redux/Zustand/React Query; `useFetch` + contexts is the contract.
- Comments only when WHY is non-obvious. No docstrings on internal helpers.
- No backwards-compat shims for behavior the user just asked you to change.
